FLYTBASE ASSET INTELLIGENCE · SYSTEM DESIGN

Fieldnote

Source-linked operational answers, with shared facts and private conversational memory.

Data and retrieval

The released snapshot contains 600 wells, 1,25,198 inspections and 17,415 maintenance records. Node.js 24 and SQLite/FTS5 retain original JSON/JSONL records, linked free-text reports, manuals, SOPs and new letters/MOC/recall documents. Newer releases supersede changed record IDs while retaining earlier versions. Type and team history, late-entered dates, cost revisions and structured corrections are applied.

Agentic layer and deterministic tools

Gemma 4 proposes a schema-constrained query plan. Literal scope, dates and operations are checked; numerical results come from linked data tools. Tools handle inspection status, gas-response deadlines, bypass timelines and memo extensions, laboratory evidence, current pump-lot inventory, cold-weather checks, reported delays and temperature comparisons. Unknown reservoir pressure, oil output and incident-specific H2S readings are not invented. Risk ranking is explicitly a heuristic judgement grounded in operator quotes and warning signs.

Memory, feedback and provenance

Each user has persistent private conversations, topic/entity sets and display preferences. “First question” returns to that session's first result set even after unrelated topics. Shared replacement reports retain the speaker, effective date, affected installation and verification state. Direct responsible-user reports are distinguished from hearsay; missing work orders remain visible. Preferences such as sorting and currency units apply only to their author. Corrections preserve originals and recompute subsequent answers.

Interface and evidence

Questions and answers are shown in a compact chat interface with cards, tables, charts and maps. Sources, complete paginated data and technical traces open on demand. Every final turn was typed through the actual browser UI under the named user/session; full response JSON and screenshots were saved. Unsupported or malformed model output is rejected, with a labeled local fallback where supported.

Models, costs and boundaries

Model: gemma-4-26b-a4b-it via Google's Gemini API. This final browser replay had 18 model-backed read turns, 3 local memory/feedback writes, and 0 provider fallbacks. Provider-reported usage: 16,392 input and 311 output tokens; failed requests may lack usage. The supplied guide describes Gemma as free-tier; invoice cost was not measured. The result is a hybrid application result, not unguarded model accuracy.

Next: broader paraphrase evaluation, stronger semantic checks for novel SQL, authenticated deployment and richer event-time memory. AI-assisted development using OpenCode; participant review and an own-voice demo are required. Application: MIT. Dataset and fictional documents: ©2026 FlytBase, MIT.

What worked and what did not

Temporal joins, changed deadlines, shared claims versus private preferences, and first-topic recall were verified. Missing measurements were reported as unavailable. The dataset does not identify every installed pump lot, so recall counts describe documented affected inventory, not proof that all other pumps are unaffected. Risk scores are not calibrated probabilities; temperature conclusions depend on stated normalization. Google returned intermittent HTTP 500s during development; this replay records the actual fallback count above.
